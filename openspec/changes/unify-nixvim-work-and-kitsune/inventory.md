# Editor comparison

The work tree at the revision in `baseline.md` is the precedence baseline. These are source observations unless a runtime check is stated.

| Area | Observed difference or risk | Intended disposition |
| --- | --- | --- |
| Composition | Work recursively imports the whole home tree; personal uses named dendritic modules. Work's Claude module is not explicitly listed by the plugins default but is discovered by the recursive import: evaluating `plugins.claudecode.enable` returned `true`. | Keep one shared export; retain Claude as a work extension and exclude the entire old work editor tree during adoption. Verify duplicate hooks. |
| Keymaps | Work uses comma as local leader; personal uses backtick. Work adds Flash incremental selection and Neotest watch, failed-test navigation and debugging mappings. | Use the work choices and check mapping conflicts. |
| Completion | Both trees configure sources in completion and LSP modules and name Tabby and Neorg without corresponding source plugins visible in the editor tree. | Consolidate sources and keep installed sources only; validate generated settings. |
| Python environment | Work adds a shared DAP/Neotest resolver and Pixi support; personal Neotest has its own resolver and synchronous direnv loading. Both modify the editor process environment. Work caches direnv before success, and writes a fixed temporary log. | Retain shared project-aware resolution and Pixi support while implementing the isolation, retry, bounded execution and logging corrections in the project-workflows spec. |
| Testing and debugging | Work configures a Python DAP adapter and test debug strategy. It adds `-n 0` to pytest and disables instance discovery; personal enables instance discovery. | Adopt work's intended DAP/test behaviour, remove the xdist-only argument, preserve work's discovery setting, and verify against a pytest-only project. |
| Notebook | Work adds Jupytext, export hooks and private Quarto-sync preview; its notebook creator opens the target for writing. Preview mapping appears both in configuration and a FileType hook. The pinned Jupytext plugin reads a same-name Markdown file as notebook content and overwrites that file when the notebook is saved. This was reproduced with disposable files. | Quarto sync is optional and notebook replacement requires confirmation. Jupytext now uses private temporary conversion files, as selected by the user. Both pinned consumers passed notebook open/save/unload tests proving a neighboring Markdown file is untouched. |
| Treesitter and LSP | Work explicitly selects grammar packages and enables Nushell LSP; its `ensure_installed` also mentions query and Typst, which are absent from its package list. | Retain the work packages and add the query and Typst packages needed by its configured language list, and enable Nushell LSP. Verify both consumer pins. |
| Assets | All 16 shared snippets and Lua files have identical contents. Work has a Markdown textobjects query; personal has an ECMA textobjects query. | Retain both queries and all shared assets, then verify their contents and installed paths. |
| Vaults | Work has a distinct Obsidian workspace; personal has two workspaces and additional frontmatter behaviour. | Keep each vault as its own consumer extension; neither belongs in the common baseline. |
| Terminal and paths | Work uses xsel and a Kitty image backend. The editor-config Telescope mapping points to a retired personal directory. | Make terminal-specific settings and the configuration directory consumer-controlled; verify each selected path and backend. |
| Overseer | Both trees configure task workflows; work invokes `direnv exec` in templates and configures a terminal strategy. Its generated initialization contains two copies of the early `overseer.setup` and a third generated setup. Work's `<leader>or`, `<leader>oo` and `<leader>ol` mappings also collide with Obsidian mappings. Neither pinned Overseer package provides the configured `toggleterm` strategy. | Use the built-in `jobstart` default without toggleterm, configure Overseer once, and assign distinct bindings. Both pinned consumers passed headless successful/failed task tests and report an empty restart list. |
| TeX | Work uses `texliveMedium`; the personal copy used the deprecated `texlive.combined.scheme-medium`. | Use work's package name, which exists on both pins. |
| Other plugin modules | Alpha, comment, Conform, Dressing, Gitsigns, Harpoon, indent-blankline, LazyGit, lint, Lualine, neo-tree, Oil, persistence, rustaceanvim, Snacks, surround, tmux navigator, Todo, Trouble, Twilight, Typst, UFO, undotree, which-key, wrapping, Zellij and Zen mode mostly differ in wrappers or formatting. Existing Overseer templates also match apart from wrappers. | Keep their common behavior; resolve the demonstrated Gitsigns/Harpoon and LazyGit mapping collisions described below. Validate active keymaps in each final consumer. |

Most identically named files differ textually because the personal tree wraps plain work-style modules in dendritic exports and uses different formatting. The comparison covers the work editor's root modules, plugins, recursive imports and all tracked snippets, queries and Lua assets. Each observed functional difference is assigned above; the work-specific consumer patch and integrated workflow checks remain separate tasks.

The generated option comparison found differences in clipboard provider, GUI font, and home-relative undo path. Generated work keymaps also include Claude and Obsidian extension mappings that are intentionally absent from the minimal personal fixture; the work configuration contains 207 map definitions and the personal fixture 159, including duplicates. These counts are not counts of unique effective mappings.

Work selects Nixvim as the default editor. The shared configuration follows that default while allowing a consumer to override it. Kitsune's theme may override the shared default GUI font.

The work clipboard setting is nested under `opts.clipboard` rather than Nixvim's `clipboard` module. A headless Neovim check of the generated value leaves `vim.o.clipboard` empty. Use a valid `unnamedplus` register and consumer-selected provider instead.

The generated work keymaps also show `<leader>hp` assigned to both Git hunk preview and Harpoon previous, and `<leader>gg` assigned twice to Lazygit. All 11 work Neotest bindings are duplicated. The shared configuration needs distinct reachable bindings for the first pair and one definition for each remaining action; assess actual runtime order and document any shortcut changes.

In the shared configuration, Harpoon keeps `<leader>hp`, Git hunk preview moves to `<leader>hP`, and the Snacks Lazygit mapping keeps `<leader>gg` (it was the later work mapping). Overseer shortcuts move together to `<leader>O` so the vault retains `<leader>o`.

The work-like Quarto-sync fixture was initialized once across Markdown and Quarto buffers and received a disposable preview path including spaces. Notebook conversion passed headless checks with both editor pins. Browser preview, image rendering, kernel execution, and clipboard integration remain real-terminal/GUI checks; the fixture does not validate the private plugin or a live preview server.
